# Backend audit, 26 October 2026

Scope: the Adam backend (`api/`, `connectors/`, `auth.js`, `scripts/`, tests). iOS (`OxyApp/`) was not touched.
Method: read the code, then fix each confirmed bug with a test and one small commit. Nothing was deployed and no paid model benchmark was run.
Result: 2148 tests, 2146 pass, 0 fail, 2 skipped (before the audit: 2117 / 2115 / 0 / 2). New tests are in `test/smoke/audit-2026-10-26.test.js`.

### Known weak spots from the brief

- **monday-train** (walking directions, no train time): confirmed. The question was classed as "pure prose" (it contains "what is"), so it took the one-pass path where `get_directions` stock text became the whole answer. Now routed to the multi-step loop (`6b306527`); the stock-line catch from `390cdc7f` was already in. Not re-run live.
- **director-score-chain** (gives up on step two): confirmed cause. "Who directed…, what is…, and is that…" was treated as one plain question and got a single search pass. Chained questions now go to the loop (`45773edf`). Not re-run live.
- **two-cities-tallest**: same routing cause ("Compare…" counted as prose). The heights themselves were right in the saved run; the failure was a missing "by how many metres" sentence. The prompt already requires it (`prompts.js` RESULTS section), so this is model completeness, worth watching rather than a code bug.
- **prague-budget** (asks for dates): ruled out as a code bug. The prompt already tells Adam to pick relative dates and only ask for dates on things to book/pay (`prompts.js` WORKING_LOOP), and the saved benchmark run passes.
- **Claude prompt caching**: confirmed and fixed (27).

### Not fixed, on purpose

- L1. `stripe_payout_to_user` is visible to the model, takes a model-chosen `destination`, and only fails today because no connected-account flow exists (it is review-gated). Tests pin its presence, so I left it. Recommend removing it from the catalog.
- L2. `connectors/oura.js` and `strava.js` use one server-wide token for every user. Neither token is set in prod, so they report unavailable. Make them per-user before enabling.
- L3. Authed cost-bearing routes with no rate limit: `/tts-preview`, `/geocode`, `/home-addresses`, `/proactive/:userId/run`.
- L4. The session check still lets a request through if the `users` lookup itself errors (fail-open on a database blip).
- L5. A one-shot reminder more than 60 minutes late is closed without telling the user (`scheduled-tasks.js` `staleScheduledReason`).
- L6. A routine that keeps failing is never paused; it retries at its normal cadence indefinitely.
- L7. `send_message` returns `pending: true` for a phone hand-off, which parks the run as "waiting for approval" with no approval row behind it.
- L8. A scene on a paired display can post "ask Adam" messages with no tap (`/display/:id/ask` is rate-limited and cannot approve anything).
- L9. `unsubscribe_email` and `clean_inbox` send mail / POST without review, by design (fixed text, reversible).

## What was checked and found clean

- Execution gate core (`action-execution.js`): review routing, delegation ordering, one failed action does not erase the batch. Approval claim is a compare-and-set (`agent-approval-runtime.js` `claimApproval`).
- `getActionContract` derives review for any `high` risk or `review` confirmation even with no `executionMode`, so the concierge/Stripe actions are gated.
- Credential grants, vault encryption (AES-GCM), session signing and expiry, OAuth state signing, Resend webhook signature, Stripe webhook signature, CORS/CSP headers, rate limiters.
- Project runtime path safety (`agent-project-runtime.js`: no absolute paths, no `..`, no symlinks, no `.git` writes, fixed check commands, env off by default).
- Display pairing (hashed codes, 8-character uniform alphabet, 5 tries), notification delivery (claim before send, no resend of an accepted message).
- Row ownership: every `.eq('id', …)` write I traced is either user-scoped or follows a user-scoped read.
- No hard-coded secrets in tracked files. Live tables: `npm run check:schema` passes (59 of 59).
- Prompts versus contracts: no contradictions found beyond the ones listed (forget_memory wording, stripe units, `time` format hint).
